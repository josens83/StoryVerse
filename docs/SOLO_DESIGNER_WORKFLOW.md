# 디자이너 없이 작업하는 워크플로우

> Solo Developer Workflow Guide 챕터 20 기반

## 개요

디자이너 없이도 품질 높은 UI를 만들 수 있습니다. 핵심은 **시스템과 도구에 의존**하는 것입니다.

## 핵심 원칙: Copy, Don't Create

**처음부터 디자인하지 마세요.** 검증된 패턴을 분석하고 재조합하세요.

### 워크플로우

```
1단계: 참조 수집 (30분)
├── 비슷한 제품 5-10개 스크린샷
├── 마음에 드는 UI 패턴 저장
└── 도구: Mobbin, Dribbble, 실제 앱

2단계: 패턴 분석 (15분)
├── 공통점 찾기 (레이아웃, 색상, 간격)
├── "왜 이렇게 했을까?" 생각하기
└── 핵심 패턴 3-5개 추출

3단계: 재조합 (구현)
├── 추출한 패턴을 프로젝트에 적용
├── AI 도구로 빠르게 프로토타입
└── 세부 조정
```

### 참조하기 좋은 제품들

| 카테고리          | 참조 제품                           |
| ----------------- | ----------------------------------- |
| 미니멀/모던       | Linear, Notion, Vercel, Stripe      |
| 대시보드          | Vercel, Railway, PlanetScale        |
| 전자상거래        | Shopify, Gumroad                    |
| SaaS              | Slack, Discord, Figma               |
| 문서/블로그       | Docusaurus, Nextra                  |
| **웹소설 플랫폼** | 네이버 시리즈, 카카오페이지, 문피아 |

## AI 디자인 도구 활용

### 추천 조합

```
v0.dev (컴포넌트) + Claude (로직) + Cursor (통합)
```

### v0.dev 사용 워크플로우

```markdown
1단계: 참조와 함께 요청
"Stripe 대시보드 스타일의 결제 내역 테이블.
날짜, 금액, 상태, 고객명 컬럼.
상태는 색상 뱃지로 표시.
shadcn/ui Table 사용."

2단계: 생성된 코드 검토

- 구조가 맞는지 확인
- 누락된 기능 체크
- 스타일 적절성 확인

3단계: 반복 수정 요청
"더 미니멀하게 해줘. 테두리 제거하고 간격 늘려줘."

4단계: 코드 내보내기

- "Code" 탭에서 복사
- 프로젝트에 붙여넣기
- 필요시 수동 조정

5단계: 프로젝트에 통합

- 실제 데이터 연결
- 타입 정의 추가
- 누락된 상태(로딩, 에러) 추가
```

## 디자인 결정 단순화 규칙

### 색상 결정

| 용도      | 선택                   |
| --------- | ---------------------- |
| 메인 액션 | primary (오렌지)       |
| 위험/삭제 | destructive (빨간색)   |
| 보조 액션 | secondary 또는 outline |
| 나머지    | muted, ghost           |

### 간격 결정

| 관계           | 간격                        |
| -------------- | --------------------------- |
| 관련 요소 사이 | 작은 간격 (gap-2, gap-4)    |
| 그룹 사이      | 중간 간격 (gap-6, gap-8)    |
| 섹션 사이      | 큰 간격 (py-12, py-16)      |
| 잘 모르겠으면  | 4의 배수 (4, 8, 16, 24, 32) |

### 크기 결정

| 요소   | 크기                                  |
| ------ | ------------------------------------- |
| 버튼   | default (대부분), sm (보조), lg (CTA) |
| 아이콘 | h-4, h-5, h-6                         |
| 아바타 | h-8, h-10, h-12                       |

### 레이아웃 결정

| 콘텐츠 타입 | 최대 너비              |
| ----------- | ---------------------- |
| 읽기 콘텐츠 | max-w-prose (65ch)     |
| 폼          | max-w-md 또는 max-w-lg |
| 카드 그리드 | max-w-7xl              |
| 전체 너비   | container mx-auto      |

## 1시간 프로토타이핑 워크플로우

```
0-10분: 참조 수집
├── 비슷한 제품 3개 스크린샷
└── 핵심 화면만 (홈, 리스트, 상세)

10-20분: 구조 스케치
├── 종이 또는 Excalidraw
├── 박스로 레이아웃만 그리기
└── 어떤 정보가 어디에 있는지만

20-40분: v0.dev로 핵심 UI 생성
├── 가장 중요한 화면 1-2개
├── 참조 이미지와 함께 요청
└── 2-3번 반복 수정

40-50분: 코드 통합
├── 생성된 코드 프로젝트에 복사
├── 기본 라우팅 연결
└── 더미 데이터로 작동 확인

50-60분: 빠른 검토 및 조정
├── 모바일 뷰 확인
├── 명백한 문제만 수정
└── 완벽하지 않아도 OK

결과: 작동하는 프로토타입 (60분)
```

## 저비용 사용자 피드백 수집

### 무료 도구

| 도구               | 기능                              | 용도             |
| ------------------ | --------------------------------- | ---------------- |
| Microsoft Clarity  | 세션 녹화, 히트맵, 분노 클릭 감지 | 사용자 행동 분석 |
| Google Analytics 4 | 페이지뷰, 이벤트 추적             | 기본 지표 파악   |
| Vercel Analytics   | Core Web Vitals, 실시간 모니터링  | 성능 추적        |

### 5명 테스트 법칙

Nielsen 연구에 따르면 **5명으로 85% 문제를 발견**할 수 있습니다.

```markdown
테스트 방법:

1. 가족, 친구에게 화면 공유
2. "이 화면에서 [작업]을 해봐" 요청
3. 막히는 부분 관찰 (말하지 말고 보기만)
4. 문제점 기록
```

## 자주 하는 실수와 해결책

| 실수              | 증상                    | 해결책                   |
| ----------------- | ----------------------- | ------------------------ |
| 완벽 추구         | "조금만 더..."가 3주째  | 80% 완성되면 출시        |
| 처음부터 디자인   | 빈 캔버스 앞에서 멍때림 | 참조 먼저 모으기         |
| 피드백 없이 개발  | 본인 눈에만 예쁨        | 5명 테스트, Clarity 설치 |
| 모바일 나중에     | 데스크톱 완성 후 대공사 | Mobile-first 개발        |
| 모든 것 직접 구현 | 버튼부터 직접 만들기    | shadcn/ui 컴포넌트 사용  |
| 상태 나중에 추가  | 로딩/에러 UI 없음       | 처음부터 4가지 상태 고려 |

## UI/UX 결정 문서화

모든 디자인 결정은 `docs/adr/` 디렉토리에 기록합니다.

### ADR 템플릿

```markdown
# ADR-UI-XXX: [제목]

## 날짜

YYYY-MM-DD

## 상태

Proposed / Accepted / Deprecated

## 컨텍스트

왜 이 결정이 필요한가?

## 고려한 옵션

1. 옵션 A: 장점/단점
2. 옵션 B: 장점/단점

## 결정

어떤 옵션을 선택했는가?

## 결과

예상되는 영향

## 참고

참조 링크, 스크린샷
```

## 출시 전 UI 점검 체크리스트

### 기본 기능

- [ ] 모든 페이지 접근 가능
- [ ] 모든 폼 제출 작동
- [ ] 에러 발생 시 적절한 메시지
- [ ] 로딩 상태 표시

### 반응형

- [ ] 모바일 (375px) 레이아웃 정상
- [ ] 태블릿 (768px) 레이아웃 정상
- [ ] 데스크톱 (1280px+) 레이아웃 정상
- [ ] 가로 스크롤 없음

### 접근성

- [ ] 키보드로 모든 기능 사용 가능
- [ ] 포커스 표시 보임
- [ ] 이미지 alt 텍스트 있음
- [ ] 색상 대비 4.5:1 이상

### 성능

- [ ] LCP < 2.5초
- [ ] 이미지 최적화됨
- [ ] 불필요한 로딩 없음

### 일관성

- [ ] 색상 일관됨
- [ ] 간격 일관됨
- [ ] 버튼 스타일 일관됨
- [ ] 타이포그래피 일관됨

### 피드백

- [ ] 1명 이상에게 테스트 받음
- [ ] 주요 문제점 해결됨
- [ ] Analytics 설치됨
