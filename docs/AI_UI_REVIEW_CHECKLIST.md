# AI 생성 UI 품질 체크리스트

> Solo Developer Workflow Guide 챕터 11 기반

## 개요

AI(Claude, Cursor 등)가 생성한 UI 코드를 수락하기 전에 반드시 확인해야 할 항목들입니다.
"작동함"과 "좋은 UX"는 다릅니다.

## AI 생성 UI의 5가지 근본적 문제

1. **Frankenstein 레이아웃**: 개별 컴포넌트는 알지만 조합 시 시각적 계층 구조 부재
2. **Happy Path만 구현**: 로딩/에러/빈 상태 누락
3. **기존 컴포넌트 무시**: 프로젝트에 있는 컴포넌트를 모르고 새로 생성
4. **접근성 무시**: alt 텍스트, 키보드 네비게이션, ARIA 속성 누락
5. **개념적 모델 부재**: 데이터 구조와 비즈니스 로직 관계 미이해

## 품질 체크리스트

### 상태 완전성 (State Completeness)

- [ ] **로딩 상태**가 구현되어 있는가?
  - Skeleton UI 사용 (Spinner보다 선호)
  - 실제 콘텐츠와 동일한 구조
- [ ] **에러 상태**가 구현되어 있는가?
  - 사용자 친화적 메시지
  - 재시도 버튼 포함
- [ ] **빈 상태(Empty State)**가 구현되어 있는가?
  - 아이콘 + 제목 + 설명
  - 다음 액션 안내 (CTA 버튼)
- [ ] **성공 상태 피드백**이 있는가?
  - Toast 또는 인라인 메시지

### 일관성 (Consistency)

- [ ] 기존 디자인 시스템 컴포넌트를 사용하는가?
  - `@/components/ui/button` 사용
  - `@/components/ui/card` 사용
  - 새로 만들지 않고 기존 것 재사용
- [ ] 색상이 디자인 토큰을 사용하는가?
  - `bg-background`, `text-foreground` 등
  - 하드코딩 금지 (`#007bff`, `bg-blue-500`)
- [ ] 간격이 일관적인가?
  - Tailwind spacing 사용 (`p-4`, `gap-6`)
- [ ] 타이포그래피가 프로젝트 스타일과 맞는가?

### 접근성 (Accessibility)

- [ ] 모든 이미지에 **의미 있는 alt 텍스트**가 있는가?
  - ❌ `alt="image"` 또는 `alt=""`
  - ✅ `alt="소설 '불멸의 대마법사' 표지"`
- [ ] 폼 요소에 **label이 연결**되어 있는가?
  - `<label htmlFor="email">` + `<input id="email">`
- [ ] **키보드**로 모든 기능을 사용할 수 있는가?
  - Tab 키로 네비게이션
  - Enter/Space로 활성화
- [ ] **색상 대비**가 충분한가? (4.5:1 이상)
- [ ] **포커스 상태**가 표시되는가?
  - `focus-visible:ring-2`
- [ ] 아이콘 버튼에 **aria-label**이 있는가?

### 반응형 (Responsiveness)

- [ ] **모바일에서 레이아웃**이 정상인가?
  - Mobile-First로 작성되었는가?
- [ ] **터치 타겟**이 충분히 큰가? (44x44px 이상)
  - `min-h-11 min-w-11`
- [ ] **가로 스크롤**이 발생하지 않는가?
- [ ] 브레이크포인트가 **표준**인가? (md, lg만 사용)

### 코드 품질 (Code Quality)

- [ ] **시맨틱 HTML**을 사용하는가?
  - `<button>`, `<nav>`, `<main>`, `<article>`
- [ ] 불필요한 **div 중첩**이 없는가?
- [ ] **하드코딩된 값** 대신 변수/토큰을 사용하는가?
- [ ] **TypeScript 타입**이 정의되어 있는가?

## Intent Prototyping 워크플로우

AI에게 바로 UI를 요청하지 말고, **먼저 개념적 모델을 정의**하세요.

### 잘못된 접근

```
"대시보드 만들어줘" → AI가 추측으로 생성 → 문제 발생
```

### 올바른 접근 (4단계)

**1단계: 개념적 모델 정의**

```
"이 대시보드의 주요 엔티티와 관계를 정의해줘:
 - 사용자(User)
 - 소설(Novel) - 사용자가 여러 개 소유
 - 챕터(Chapter) - 소설에 속함
 - 상태: draft, published, deleted"
```

**2단계: 사용자 플로우 정의**

```
"핵심 사용자 플로우:
 1. 로그인 → 대시보드 (소설 목록)
 2. 소설 선택 → 챕터 목록
 3. 챕터 작성 → 저장 → 발행"
```

**3단계: 상태 정의**

```
"각 화면의 상태:
 - 로딩 중 (Skeleton)
 - 데이터 있음 (성공)
 - 데이터 없음 (빈 상태)
 - 에러 발생 (재시도)"
```

**4단계: 이제 UI 요청**

```
"위 정의를 바탕으로 소설 목록 컴포넌트를 구현해줘.
 기존 컴포넌트 사용: Button, Card, Skeleton, EmptyState
 DataContainer로 4가지 상태 처리"
```

## 빠른 검토 질문

AI가 생성한 UI를 받으면 다음 질문을 던지세요:

1. "로딩 중일 때 어떻게 보이지?"
2. "데이터가 없으면 어떻게 보이지?"
3. "에러가 나면 어떻게 보이지?"
4. "모바일에서는 어떻게 보이지?"
5. "키보드로 사용할 수 있어?"
6. "기존 Button/Card 컴포넌트 썼어?"
